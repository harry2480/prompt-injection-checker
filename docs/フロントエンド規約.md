# プロンプトインジェクション検査サイト フロントエンド規約

Next.js App Router（静的エクスポート） + shadcn/ui + Tailwind CSS におけるフロントエンド規約。

---

## ディレクトリ構成

`apps/webapp/src/` 配下:

| ディレクトリ | 責務 |
|---|---|
| `app/` | ページ（`page.tsx` / `layout.tsx`）。静的生成のエントリ |
| `frontend/components/` | React コンポーネント。`'use client'` でクライアントを明示 |
| `frontend/components/ui/` | shadcn/ui コンポーネント |
| `frontend/components/inspection/` | 検査機能の UI（入力・結果・ハイライト） |
| `frontend/hooks/` | カスタム hooks（`use-inspection.ts` 等） |
| `frontend/lib/` | クライアント側 util（`cn` 等） |
| `backend/` | 検知ロジック（`アーキテクチャ.md` 参照） |

---

## Server Components / Client Components の使い分け

- **デフォルトは Server Component。** `'use client'` は必要な場合のみ付与する
- 静的な骨組み（レイアウト・見出し・説明文・ルールカタログ等）は Server Component で静的生成する
- **検査 UI は Client Component。** テキスト入力・ボタン操作・ファイル読込・ブラウザ内検知の実行はすべてクライアントで行うため `'use client'` を付与する
- **サーバーでのデータ取得（loader）は行わない。** サーバーが存在しないため、初期表示は静的コンテンツのみ。動的な検査はクライアントで完結する

---

## データフローと状態管理

- **状態管理**: React 標準（`useState` / `useReducer`）を最小限に使用する。グローバル状態管理ライブラリ（Zustand / Redux 等）は原則不使用
- **検知の呼び出し**: UI は `backend/presentation/composition` が公開する検査 UseCase を、カスタムフック（`use-inspection.ts`）経由で呼び出す。UI から `backend/domain` や `infrastructure` を直接 import しない
- **検知ロジックを UI に書かない**: 正規表現・辞書・Unicode 解析等の検知ロジックは必ず `backend/domain` に置く。コンポーネントは入力を渡し、結果を描画するだけに保つ
- **ミューテーション / 永続化**: なし。検査結果はコンポーネントのローカル状態にのみ保持し、リロードでリセットする（外部送信・保存しない）

---

## 入力・結果表示の指針

- **入力ソース切替**（テキスト／ファイル／URL）は 1 つの検査対象を選ぶ UI とする
- **ハイライト表示**: 検出結果の文字位置（range）に基づきマッチ箇所を強調する。位置情報は検知エンジンの戻り値から受け取る
- **不可視文字**: ゼロ幅文字・制御文字は「⟨ZWSP⟩」等の可視ラベルに置換して表示し、隠された文字の存在を明示する
- **免責表示**: 「一次スクリーニングであり結果を保証しない」旨を結果エリアに常時表示する
