# プロンプトインジェクション検査サイト 品質チェック規約

`vitest` + `TypeScript` + `dependency-cruiser` + `Biome` によるコード品質チェック規約。
**DB を持たない静的サイト**のため、DB マイグレーション（prisma generate 等）や Integration（DB 接続）テストは含めない。

---

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| Unit テスト | vitest | domain（検知エンジン・ルール・モデル）, application（UseCase） | `pnpm test:unit` |
| 型チェック | `tsc --noEmit` | 全ソース | `pnpm typecheck` |
| 依存方向チェック | dependency-cruiser | 全ソース | `pnpm depcruise` |
| リンター / フォーマッター | Biome | 全ソース | `pnpm lint` |
| ビルド検証（任意） | Next.js（`output: 'export'`） | 静的エクスポート成功確認 | `pnpm --filter webapp build` |

> Integration テスト（DB 接続）と `prisma generate` は本プロダクトでは**不使用**。

### verify コマンド 実行フロー

`pnpm verify` は以下の順序で実行されることを期待する：

1. lint（Biome: フォーマット + lint）
2. typecheck（`tsc --noEmit`）
3. unit test（`pnpm test:unit`）
4. depcruise（依存方向チェック）

コード変更後は必ず実行し、全パスすることを確認する。

> テンプレート標準の `prisma generate`（型生成）ステップは DB を持たないため verify から除外する。

---

## 型チェック (TypeCheck)

- `tsc --noEmit` で型エラーがないことを確認する
- **`any`** の使用は原則禁止（一時的な回避には lint 抑制コメントを明確に併記する）
- 検知結果の型（`DetectionResult` / `RiskScore` / カテゴリの列挙等）は `backend/domain` に定義し、frontend と共有して二重定義を避ける
- CI で必ず実行。型エラーがある PR はマージ不可とする

---

## 依存方向チェック (Dependency Cruise)

- `アーキテクチャ.md` で定義した依存方向をチェックする：
  `presentation → application → domain ← infrastructure`
- 特に以下を機械的に禁止する：
  - **domain が他層・ブラウザ API に依存すること**（純粋ロジックを保つ）
  - **frontend が backend/domain・infrastructure を直接 import すること**（`backend/presentation/composition` 経由のみ許可）
  - **application が infrastructure を直接 import すること**（Gateway interface 経由のみ）
- 違反があった場合、モジュールの切り出し・配置を見直す

---

## Lint / Format (Biome)

- Biome でフォーマットと lint を一元管理する
- `pnpm lint:fix` で自動整形する
- import 順・未使用変数・命名（kebab-case ファイル名 + レイヤーサフィックス）を含めてチェックする

---

## 静的エクスポートの健全性

- サーバー機能（Server Actions・API Routes・動的 `next/image`）を誤って使用していないこと
- `pnpm --filter webapp build` が `output: 'export'` で成功し、`out/` が生成されること
- バンドルにシークレット・秘密情報が含まれていないこと（本プロダクトはシークレットを持たない）
