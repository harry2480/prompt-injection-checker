# プロンプトインジェクション検査サイト インフラ規約

pnpm workspace + GitHub Pages（静的ホスティング）によるインフラ環境の構成と規約。
**サーバー・DB・外部サービスを持たない静的サイト**であり、デプロイ先は GitHub Pages に一本化する。

---

## Monorepo 構成

pnpm workspace で管理。`apps/` 配下に Web アプリを配置する。

```text
prompt-injection-checker/
├── apps/
│   └── webapp/          # Next.js 15 アプリ（静的エクスポート）
├── docs/                # 設計ドキュメント
├── pnpm-workspace.yaml
├── biome.json           # 共有 lint/format 設定
└── package.json         # workspace scripts
```

---

## 静的エクスポート設定

GitHub Pages は静的ファイルのみを配信するため、Next.js を静的エクスポートで出力する。

```ts
// apps/webapp/next.config.ts（要点）
const nextConfig = {
  output: 'export',           // 静的 HTML/JS を out/ に出力
  images: { unoptimized: true }, // Image Optimization（サーバー機能）を無効化
  // リポジトリ配下配信の場合は basePath / assetPrefix を設定
  // basePath: '/prompt-injection-checker',
};
```

- **サーバー機能は使用不可**: Server Actions・API Routes・`next/image` の最適化・ISR/SSR は使えない。すべて静的生成（SSG）＋クライアント実行で完結させる
- **basePath**: `<user>.github.io/prompt-injection-checker/` のようなサブパス配信時は `basePath` / `assetPrefix` を設定する。独自ドメイン／ユーザーサイト配信時は不要

## デプロイメント

| 環境 | トリガー | プラットフォーム | 備考 |
|---|---|---|---|
| Preview | PR 作成 / 更新 | GitHub Actions でビルド検証（デプロイはしない） | PR ごとに build が通ることを確認 |
| Production | `develop`（または `main`）への push | GitHub Actions → GitHub Pages へ自動デプロイ | `out/` を Pages に公開 |

### GitHub Actions（概要）

```yaml
# .github/workflows/deploy-pages.yml（概要）
# 1. pnpm install
# 2. pnpm --filter webapp build   (output: 'export' で out/ を生成)
# 3. actions/upload-pages-artifact で out/ をアップロード
# 4. actions/deploy-pages で GitHub Pages へデプロイ
```

- リポジトリ設定の **Settings → Pages → Source を「GitHub Actions」** に設定する
- Node.js Version: 20.x 以上
- Build Command: `pnpm --filter webapp build`
- 出力ディレクトリ: `apps/webapp/out`

## 環境変数・シークレット

- **本プロダクトはシークレットを持たない。** 検知はクライアントで完結し、API キー・DB 接続情報は不要
- 静的サイトにバンドルされる値はすべて公開される前提。秘密情報を埋め込まないこと
- 将来 BYOK（利用者が自身の API キーを入力）を導入する場合も、キーは**ビルドに埋め込まず**ブラウザのローカル（メモリ / `localStorage`）でのみ保持する

---

## DB・外部サービス

- **DB は使用しない。** Supabase・Prisma 等のデータストアは本プロダクトの対象外
- URL取得機能で外部通信が発生する場合のみ、CORS 制約と取得先の扱いに注意する（要件定義 §10 参照）
