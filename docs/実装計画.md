# プロンプトインジェクション検査サイト 実装計画書

`要件定義.md` に基づき、Next.js 15（静的エクスポート）+ ルールベース検知エンジンによる実装手順を示す計画書。
検知はすべてブラウザ内で完結し、サーバー・DB・API キーを持たない。

## 1. 実装フェーズ

### Phase 1: 環境構築・静的エクスポート設定
- Next.js 15 (App Router) の静的エクスポート設定（`output: 'export'`, `images.unoptimized`）
- Tailwind CSS + shadcn/ui セットアップ
- Biome / vitest / dependency-cruiser の設定
- GitHub Actions（build → GitHub Pages デプロイ）ワークフロー作成

### Phase 2: 検知エンジン実装（domain）
- ドメインモデル（`DetectionResult`, `RiskScore`, カテゴリ列挙）の定義
- 検知ルール定義（`domain/rules/`）: 日本語 / 英語 / 言語非依存
- 検知サービス（`domain/services/injection-detector.service.ts`）: ルール適用・位置算出・スコアリング
- Unit テスト（陽性・陰性ケース）

### Phase 3: 入力・オーケストレーション（application / infrastructure）
- Gateway interface（`ContentSourceGateway`）とアダプタ実装（本番 + Stub）
- 検査 UseCase（`inspect-text.usecase.ts`）
- Composition Root で DI 組み立て

### Phase 4: UI 実装（frontend）
- 入力 UI（テキスト貼り付け / ファイル / URL 切替）
- 結果表示 UI（総合リスク・カテゴリ別サマリー・ハイライト・検出リスト）
- 不可視文字の可視ラベル化・免責表示
- カスタムフック（`use-inspection.ts`）

### Phase 5: 統合・検証
- `page.tsx` への統合
- `pnpm verify` 通過確認
- GitHub Pages へのデプロイ確認・動作確認

### 2.4 実装詳細

#### 検知ルールの型（`domain/rules/rule.types.ts`）

```typescript
export type InjectionCategory =
  | 'instruction-override'   // 命令の無視・上書き
  | 'role-change'            // 役割・人格の変更
  | 'system-prompt-leak'     // システムプロンプト/機密の抽出
  | 'restriction-bypass'     // 制約解除・特権要求
  | 'role-marker-injection'  // 区切り/ロールマーカー注入
  | 'hidden-character'       // 不可視文字・難読化
  | 'encoded-payload'        // エンコード隠蔽
  | 'data-exfiltration'      // データ持ち出し・外部誘導
  | 'action-inducement';     // ツール/行動の誘導

export type RuleLanguage = 'ja' | 'en' | 'any';

export interface InjectionRule {
  id: string;
  category: InjectionCategory;
  language: RuleLanguage;
  weight: number;                 // リスクスコアへの寄与
  description: string;            // なぜ危険か（UI 表示用）
  // マッチ関数: 入力を受け取り、検出範囲の配列を返す純粋関数
  match: (input: string) => Array<{ start: number; end: number; value: string }>;
}
```

#### 検知サービス（`domain/services/injection-detector.service.ts`）

```typescript
import type { InjectionRule } from '../rules/rule.types';
import { DetectionResult } from '../models/detection-result.model';

export class InjectionDetectorService {
  constructor(private readonly rules: readonly InjectionRule[]) {}

  // 純粋関数: 入力に全ルールを適用し、検出結果を返す（外部依存・副作用なし）
  inspect(input: string): DetectionResult {
    const detections = this.rules.flatMap((rule) =>
      rule.match(input).map((m) => ({ rule, ...m })),
    );
    return DetectionResult.from(input, detections);
  }
}
```

#### 検査 UseCase（`application/usecases/inspect-text.usecase.ts`）

```typescript
import type { ContentSourceGateway } from '../../domain/gateways/content-source.gateway';
import type { InjectionDetectorService } from '../../domain/services/injection-detector.service';
import type { DetectionResult } from '../../domain/models/detection-result.model';

type Source =
  | { kind: 'text'; text: string }
  | { kind: 'file'; file: File }
  | { kind: 'url'; url: string };

export class InspectTextUseCase {
  constructor(
    private readonly detector: InjectionDetectorService,
    private readonly contentSource: ContentSourceGateway,
  ) {}

  async execute(source: Source): Promise<DetectionResult> {
    const text =
      source.kind === 'text'
        ? source.text
        : source.kind === 'file'
          ? await this.contentSource.readFile(source.file)
          : await this.contentSource.fetchUrl(source.url);
    return this.detector.inspect(text);
  }
}
```

#### Composition Root（`presentation/composition/inspection.composition.ts`）

```typescript
import { InjectionDetectorService } from '../../domain/services/injection-detector.service';
import { InspectTextUseCase } from '../../application/usecases/inspect-text.usecase';
import { BrowserContentSourceAdapter } from '../../infrastructure/adapters/browser-content-source.adapter';
import { jaRules } from '../../domain/rules/ja-rules';
import { enRules } from '../../domain/rules/en-rules';
import { structuralRules } from '../../domain/rules/structural-rules';

export function createInspectTextUseCase(): InspectTextUseCase {
  const detector = new InjectionDetectorService([
    ...jaRules,
    ...enRules,
    ...structuralRules,
  ]);
  const contentSource = new BrowserContentSourceAdapter();
  return new InspectTextUseCase(detector, contentSource);
}
```

#### カスタムフック（`frontend/hooks/use-inspection.ts`）

```typescript
'use client';

import { useState } from 'react';
import { createInspectTextUseCase } from '@/backend/presentation/composition/inspection.composition';
import type { DetectionResult } from '@/backend/domain/models/detection-result.model';

const inspectText = createInspectTextUseCase();

export function useInspection() {
  const [result, setResult] = useState<DetectionResult | null>(null);
  const [isInspecting, setIsInspecting] = useState(false);

  async function inspect(text: string) {
    setIsInspecting(true);
    try {
      setResult(await inspectText.execute({ kind: 'text', text }));
    } finally {
      setIsInspecting(false);
    }
  }

  return { result, isInspecting, inspect };
}
```

## 3. 検知ルールの初期セット（例）

| カテゴリ | 日本語パターン例 | 英語パターン例 |
|---|---|---|
| instruction-override | これまでの/以上の指示を無視・忘れて | `ignore (all )?previous instructions`, `disregard the above` |
| role-change | あなたは今から〜／〜として振る舞って | `you are now`, `act as`, `pretend to be`, `DAN` |
| system-prompt-leak | システムプロンプトを教えて／初期設定を出力 | `reveal your system prompt`, `print your instructions` |
| restriction-bypass | 制限なしで／開発者モード／フィルター無効化 | `no restrictions`, `developer mode`, `jailbreak` |
| role-marker-injection | `### System:` / `SYSTEM:` / `<\|im_start\|>` / `[INST]` | 同左（言語非依存） |
| hidden-character | ゼロ幅 (U+200B/C/D/FEFF)・双方向制御 (U+202E)・Tag 文字 | 同左（言語非依存） |
| encoded-payload | 長い Base64 / Hex / URL エンコードらしき列 | 同左（ヒューリスティック） |
| data-exfiltration | 次の URL に送信／`![](http://…?q=)` | `send to`, markdown image exfiltration |
| action-inducement | 実行して／削除して | `run this command`, `execute`, `delete` |

## 4. 完了条件（要件定義 §12 と対応）

1. テキスト貼り付けで代表的インジェクション（日英）を検知・ハイライトできる
2. ファイル読込で同様に検査できる（外部送信なし）
3. 主要カテゴリ（命令上書き・ロールマーカー・不可視文字等）を検出できる
4. 総合リスク・カテゴリ別サマリー・検出根拠を表示できる
5. GitHub Pages 上でサーバーなしで動作し、入力が外部送信されない（URL取得を除く）
6. 検知関数の Unit テストが存在し、`pnpm verify` が通る
